## High value

1. [ ] **[S]** _Accessibility_ — The app has exactly one `accessibilityLabel` (run today: `grep -c` over `app` + `src` = 1). Icon-only buttons (set complete, add set, rest timer +/-15 s, menu buttons) are unlabeled for TalkBack/VoiceOver. Add `accessibilityRole`/`accessibilityLabel`/`accessibilityState` to every Touchable in `SetRow`, `ExerciseBlock`, `RestTimerBar`, `WorkspaceHeader`, and tab bar items.
2. [ ] **[S]** _Bug_ — The Epley 1RM formula `weight * (1 + reps / 30)` is duplicated in `goalQueries.getGoalProgress`, `statsQueries.getOneRMHistory` and likely elsewhere as raw SQL, with no cap on reps; a 30-rep set claims a 2x 1RM and drives goals to "achieved" incorrectly. Centralize one `e1rmSql` fragment in `sqlFragments.ts`, cap reps at 10-12 (older item), and unit-test it.
3. [ ] **[S]** _Data_ — No schema index exists yet. `grep CREATE INDEX` over `src` and `app` returns nothing (run today), so the history/PR/ghost-set queries from `TODO_CODE_REVIEW.md` still scan `logged_exercises` and `logged_sets` in full. Add a numbered migration (5) creating `idx_le_exercise`, `idx_le_workout`, `idx_ls_exercise` and `idx_workouts_finished`; it is the cheapest speed-up and unblocks 1-year histories.
4. [ ] **[S]** _Data_ — Backup must cover photos and pending WAL (older item). Beyond `VACUUM INTO`, define the backup as one zip containing `konafit.db`, `photos/` and a `manifest.json` (app version, schema `user_version`, date), and make restore refuse a backup from a newer schema than the app knows.
5. [ ] **[S]** _Data_ — Progress photos reference absolute `file://` paths (older item); additionally nothing deletes the photo file when its DB row is removed or when "Wipe All Data" runs. Add a cleanup that removes orphan files in the photos folder on launch and on wipe.
6. [ ] **[S]** _Data_ — Session snapshot is stored under the old key `@kinetic_active_session` (from a previous app name) in `kv_store`; renaming needs a migration that moves the value, otherwise a future rename silently orphans an in-progress workout. Use a versioned key and store `schemaVersion` inside the snapshot so an old snapshot is rejected rather than crashing `JSON.parse` consumers.
7. [ ] **[S]** _Feature_ — Auto-start the rest timer when a set is ticked (older item), driven by a setting with per-exercise overrides (heavy compounds 3 min, isolation 60 s) and RPE-aware suggestions (RPE 9+ → add 30 s).
8. [ ] **[S]** _Quality_ — Add on-device end-to-end tests for the core loop (start workout, log set, finish, see history, undo) with Maestro (YAML, no code) in CI via EAS build or an Android emulator; unit tests cover queries and reducers but nothing exercises the screens.

Schedule a local notification at `endTimeRef` with `expo-notifications` when the timer starts and cancel on stop/adjust; use `expo-keep-awake` only while the app is foregrounded.
