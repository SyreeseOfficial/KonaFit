Reviewed 2026-10-08. **Not repeated here:** everything already in `TODO_CODE_REVIEW.md` (38 items: discard bug, N+1 queries, missing indexes, debounce, a11y labels, onboarding, store readiness). ## Skipped for now
- [ ] **[H]** Rest timer never auto-starts. `handleSetComplete` only fires a haptic (`app/(tabs)/train.tsx:203-207`); `restTimer.start` is only called by the bar's manual button (`RestTimerBar.tsx:31`). The setting sublabel and README both promise auto-start. Call `restTimer.start()` when a non-warmup set is completed (optionally skip on the last set of the last exercise).
- [ ] **[M]** Rest timer end has no cue: no haptic, sound, or notification when it hits 0 (README promises vibration + crimson flash). Add `Haptics.notificationAsync(Success)` on completion; add `expo-notifications` local notification so it still fires with the screen locked.
- [ ] **[H]** Progressive overload hints: on each exercise show "last time 135 x 8: try 140 x 8 or 135 x 9" using existing ghost data.
- [ ] **[M]** Weekly goal (e.g. 4 workouts/week) with a weekly streak. Daily streaks punish rest days (spec itself says "week or day"). Reuses the existing `workouts` table.
- [ ] **[M]** Body measurements beyond weight (waist, arms, etc.) and photo comparison side-by-side in `ProgressPhotoGallery`.
- [ ] **[M]** Starter programs bundled (PPL, Upper/Lower, 5x5). Already in TODO as onboarding; add 3-4 with proper rep ranges and RPE targets.
- [ ] **[L]** Apple Health / Health Connect sync for bodyweight and workouts.
- [ ] **[L]** Interval/timer mode for cardio and core exercises (`target_type` column already exists on `exercises`).
- [ ] **[L]** Home-screen widget or notification action to start a workout.
- [ ] **[H]** No backup or restore. The app is local-only, so a lost/broken phone loses all history. Export is CSV only and cannot be imported back. Add: "Back up database" (copy `konafit.db` via `expo-file-system` + `expo-sharing` to Drive/Files) and "Restore from backup". JSON export of all tables is the portable alternative.
- [ ] **[H]** Android CSV export shares the whole file as a text message (`exportUtils.ts:416`), which fails for big histories (Binder size limit ~1 MB). Write the file to cache and share it with `expo-sharing` on both platforms.
- [ ] **[M]** Auto-backup a snapshot before "Wipe All Data" and before each DB migration.
- [ ] **[M]** README says CSV/**Excel** export and Markdown + PNG share. Only CSV and Markdown text are in `exportUtils.ts`; verify the PNG path (`WorkoutShareCard`) works, and fix README wording.
- [ ] **[M]** Strength score `categorizeExercise` mismatches (`src/utils/strengthScore.ts:82-86`): `row` matches "Upright Row" (delts); `fly` matches "Reverse Fly" (rear delts); `leg press` counts as squat (1RM is often 2-3x squat, inflating the score); `hip thrust`/`good morning` count as deadlift; `dip` also matches substrings. Use an explicit exercise-id/name map, or a `lift_category` column on `exercises`.
- [ ] **[M]** 1RM estimate uses Epley for any rep count (`statsQueries.ts:186,205`, `goalQueries.ts:86`). At 15+ reps it overstates badly. Cap input at 10 reps (ignore higher), or use Brzycki below 10.
- [ ] **[M]** Overall strength score averages only categories you have logged (`strengthScore.ts:141`), so one great lift = "Elite". Show overall as "N of 5 lifts tracked" or count missing lifts as 0.

### Bugs and data integrity
- [ ] **[H]** The root layout renders before the database is ready. `RootLayout` (`app/_layout.tsx:37-41`) calls `initializeDatabase()` in an effect but renders `<Stack>` as soon as fonts load, so on first launch (and on any launch with a pending migration) Train's `useFocusEffect` queries and the session-recovery check run against tables that don't exist yet or are half-migrated, and `console.error` is the only failure handling. Keep a `dbReady` state, render the splash/blank view until it is true, and show a retry/error screen if init throws.
- [ ] **[H]** "Copy last set to all" plus an early Finish completes sets you never did. `copyLastSetToAll` writes weight/reps into every unticked set (`useWorkoutSession.ts:356` -> `upsertLoggedSet`), and `finalizeWorkout` then marks every row with weight+reps as completed (`workoutQueries.ts:17`). Copy to 4 sets, do 2, hit Finish: all 4 count toward volume, PRs, streak and "Total Lifted". Either remove the auto-complete and only trust ticked sets, or ask at Finish ("3 filled sets aren't ticked: count them / skip them").
- [ ] **[M]** Fresh installs get duplicate exercises. `seedDefaultExercises` inserts `ALL_EXERCISES` with no name check (`database.ts:516`), and the list contains the same name twice: `Stiff-Leg Deadlift` (Lower Back + Hamstrings), `Good Morning` (Lower Back + Hamstrings), `Reverse Curl` (Biceps + Forearms). Two ids means two separate histories, PR sets and ghost data for one movement. The upgrade path (`seedExpandedExercises`) dedupes by name, so only new installs are affected. Near-duplicates also exist (`Band Pull-Apart`/`Banded Pull-Apart`, `Hyperextension`/`Back Extension`, `Reverse Hyperextension`/`Reverse Hyper`). Dedupe the list, merge existing duplicate ids in a migration (repoint `logged_exercises.exercise_id`, `program_exercises`, `goals`), then add a unique index on `LOWER(name)` and block duplicate custom exercises in `createCustomExercise`.
- [ ] **[M]** "Volume" means four different things. `getVolumeByMuscle` has no `is_warmup = 0` and no `finished_at IS NOT NULL` filter (`statsQueries.ts:231`); `getStatsTotals.lifted` counts warmups and the unfinished in-progress workout (`:73`); `getWorkoutHistory.total_volume` and `getWorkoutDetail.totalVolume` count warmups; `getVolumeTrend`/PR queries exclude them. Put the working-set filter in one SQL view (`CREATE VIEW working_sets`) or fragment and use it everywhere, then add a test that the numbers agree.
- [ ] **[M]** Saving a workout as a program can create an exercise with zero sets. `createProgramFromWorkout` sets `target_sets = COUNT(completed non-warmup sets)` (`programQueries.ts:318`), which is 0 for an exercise nothing was ticked on, and `launchFromExercises` only falls back to 3 when `targetSets` is null (`useWorkoutSession.ts:537`), so the launched exercise has no set rows. Use `MAX(1, ...)` like `getLastWorkoutExercises` does.
- [ ] **[M]** Progress photos store an absolute `file://` path (`train.tsx:204-209` -> `saveProgressPhoto(dest)`). On iOS the app container path changes across updates and restores, so every saved photo breaks. Store just `photo_<ts>.jpg` and resolve against `FileSystem.documentDirectory` at read time. Related: `deleteProgressPhoto` removes the row but leaves the file on disk, and `handleCameraPress` asks for media-library permission before offering "Camera" (`train.tsx:78`), so a user who only wants the camera is blocked by an unrelated denial.
- [ ] **[M]** Weekly Goal does nothing. `getWeeklyGoal()` is only read by Settings itself (`settings.tsx:123`); no Train/Stats screen shows progress toward it. Same class of bug as the Default Rest Timer that was fixed earlier. Show "2 / 4 this week" on Train and Stats, or remove the setting.
- [ ] **[M]** Workout duration includes idle time. `duration_seconds = unixepoch() - started_at` (`workoutQueries.ts:28`), so a session left open over lunch (or forgotten overnight and resumed from the recovery prompt) adds hours to "Hours" and to the history. `logged_sets.created_at` is set at row creation, not completion, so there is no timestamp to fall back on. Add `completed_at` to `logged_sets` (migration 4), then let Finish default to "last completed set + 2 min" and allow editing the end time.
- [ ] **[M]** `launchFromExercises` is not atomic (`:518`): it creates the workout row, then loops through inserts. A failure partway leaves an unfinished workout with no session. Run it in `withTransactionAsync`, and on startup delete unfinished workouts that aren't the cached session.
- [ ] **[L]** `swapExercise` leaves old and new `use_count` unbalanced (`:485`), doesn't load the new exercise's library note, and keeps already-ticked sets (so PR badges on them were computed against the previous exercise). Confirm the swap when sets exist and reset `prBadges`.
- [ ] **[L]** `getLastWorkoutExercises` counts every non-warmup set including unticked ones for `targetSets` (`historyQueries.ts:75`) and drops warmups and superset grouping, so "Repeat Last Workout" doesn't repeat the structure. Count completed sets, and carry `superset_id`.
- [ ] **[L]** `handleSaveWorkout` has no `try/catch` around `finishWorkout()` (`train.tsx:248`). If the DB write fails, the sheet has already closed, no navigation happens and no error is shown.
